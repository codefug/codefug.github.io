API 계층 재설계 제안과 팀 단위 점진 전환

  • Server Action 기반 API 계층은 요청이 순차 처리돼 네트워크 워터폴이 불가피했고, 배포 때마다 Version Skew로 요청이 실패했으며, MSW 같은 서드파티 라이브러리와의 호환도 떨어졌습니다. 전환의 트레이드오프를 정리해 tRPC 기반 재설계를 제안했고, 논의를 거쳐 팀의 방향으로 채택됐습니다.
  • 팀원들과 도메인 단위로 점진 이관해 운영 중단 없이 전환을 마쳤고, 배포 시 요청 실패가 해소되며 메인 페이지 네트워크 요청 시간이 49% 감소했습니다. 전환으로 비로소 가능해진 tRPC-MSW 모킹 환경을 구축해 E2E와 스토리북까지 통합했습니다.

선정산 신청 상태를 타입으로 차단

  • 일부 프로퍼티가 Optional로 정의돼 상태별로 어떤 값이 유효한지 코드만으로 알 수 없던 선정산 신청 로직을 Discriminated Union 기반으로 재설계해, 잘못된 상태 조합이 타입에서 차단되게 했습니다.
  • 존재할 수 없는 상태가 사라져 화면 코드가 읽기 쉬워졌고, 새 신청 유형도 타입 하나만 추가하면 되는 구조가 됐습니다.

오버레이 우선순위 중앙화

  • 따로 상태를 관리하며 겹치거나 묻히던 자동 노출 오버레이의 렌더링을 OverlayCoordinator로 중앙화해, 충돌 시 우선순위가 가장 높은 하나만 노출되게 했습니다. 우선순위가 선언된 배열 순서 하나로만 정의되어, 오버레이가 늘어나도 z-index 개별 대응 없이 일관되게 동작합니다.
  • 모달 라이브러리로 해결되지 않는 조건부 자동 노출을 전역에서 관리하는 구조로, 기획팀과 디자인팀에 서비스 방향을 확인해 필요를 검증한 뒤 설계했습니다.
