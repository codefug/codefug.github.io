API 계층 tRPC 전환 제안과 점진 이관

  • Server Action 기반 API 계층에서는 요청이 순차 처리돼 워터폴이 불가피했고, 배포마다 Version Skew로 요청이 실패했으며, MSW와도 호환되지 않았습니다.
  • 기존 개발 구조와 다르지 않으면서 부가 기능을 갖춘 기술을 찾아 tRPC 전환을 제안해 팀에 채택됐고, 도메인 단위로 운영 중단 없이 이관했습니다.
  • 그 결과 첫 화면의 전체 데이터 요청 시간이 49% 줄었고 배포 직후 요청이 실패하던 일이 사라졌으며, tRPC-MSW 핸들러 하나로 E2E와 스토리북의 모킹을 통합하고 MSW 환경을 구축했습니다.

  • 로그인 여부와 뷰포트를 클라이언트에서만 판정해, 상품마진과 정산달력 같은 핵심 페이지의 서버 HTML에는 스켈레톤과 GNB, 푸터만 담기고 크롤러가 본문을 읽지 못했습니다.
