Next.js, TypeScript, tRPC, Tanstack Query, Zustand, Playwright

tRPC 기반 API 계층 구축

  • Server Action 기반 기존 API 계층은 요청이 순차 처리돼 네트워크 워터폴이 불가피했고(직접 측정 (https://codefug.github.io/posts/2026-01-29)), 배포 때마다 버전 스큐로 기존 요청이 실패하는 문제가 반복됐습니다. mutation을 위한 기술이라 MSW를 비롯한 서드파티 호환 문제도 잦았습니다.
  • 한 번에 바꿀 수 없어 여러 도메인을 순차 이관 — 정의 → 훅 전환 → 소비처 교체 → 목 작성 → 레거시 제거를 반복하고 완주 후 구 인프라를 제거해, 흩어져 있던 엔드포인트를 단일 경로로 모았습니다.
  • 요청이 병렬로 처리되며 성능이 개선되고 배포 시 실패 현상이 사라졌습니다. 호환성이 풀리면서 MSW 기반으로 모킹 환경을 전면 개편해, 스토리북과 E2E가 같은 목을 쓰는 개발 환경을 만들었습니다.

서버 응답 기반 세션 처리 구조

  • "작업 도중 갑자기 로그아웃된다"는 운영 문의가 반복됐습니다. 원인은 클라이언트가 자체 계산한 시각으로 만료를 판단해 서버와 기준이 어긋난 것이었고, 인증 상태를 관리하는 객체도 여러 곳에 흩어져 서로 다른 시점에 판단하고 있었습니다.
  • 판단 기준을 서버로 일원화하고 인증 상태를 단일 출처로 통합해, 프론트가 만료 시점을 추측하지 않고 중복 관리 객체도 제거했습니다.
  • ISMS 인증 요건에 맞춰 비활동 세션 자동 만료 등 보안 정책을 함께 반영한 구조로 설계했습니다.

판별 유니온 기반 신청 상태 모델

  • 신청 상태가 boolean·enum 조합으로 흩어져 값이 있어선 안 되는 상태에서도 필드에 접근할 수 있었습니다. 판별 유니온으로 재정의하고 해당 필드를 아예 제거해 잘못된 조합을 컴파일 단계에서 차단했습니다.
  • 자식마다 흩어져 있던 금액 계산을 상위로 모아 자식은 렌더링만 담당하게 분리하고, 계산 로직은 순수 함수로 떼어 단위 테스트로 보호했습니다.

오버레이 우선순위 조정 시스템

  • 조건에 따라 자동으로 뜨는 오버레이들이 각자 상태를 들고 있어 겹쳐 뜨거나 필수 모달이 묻혔고, z-index로만 막고 있어 "누가 우선인가"가 어디에도 정의되어 있지 않았습니다. 그때마다 개별 대응이 반복됐습니다.
  • 각 오버레이는 노출 의사만 선언하고 우선순위가 활성 하나를 결정하는 구조로 통합했습니다 — 겹침을 관리하는 대신 동시에 두 개가 활성될 수 없게 만들어, 닫히는 중 재클릭으로 생기던 중복 요청도 함께 해결했습니다.

서류 첨부 공용 상태 머신

  • 서류를 냈는데 저장되지 않는다는 제보가 재현되지 않아, 프론트·백엔드 로그를 시간순으로 맞춰 추적했습니다. 응답 코드가 검증 스키마에 없어 원인 메시지가 사라진 채 다른 에러로 바뀌고 있었고, 결함 하나가 아니라 셋이 연쇄하고 있었습니다.
  • 여러 흐름이 서류 첨부를 각자 구현하며 확정 요청 결과를 확인하지 않고 화면을 닫고 있었고, 업로드가 스스로를 재호출하는 경로도 일부 분기에만 있어 오래 드러나지 않았습니다.
  • 공용 상태 머신으로 통합하고 전이를 유저 액션에서만 일으키도록(effect 없이) 바꿨습니다. 서로 다른 업로드 결과가 섞이는 조합은 타입에서 차단했습니다 — 유저당 재시도 58% 감소, 계약 체결 소요 84% 단축

E2E 확장과 CI 파이프라인 최적화

  • 테스트가 늘수록 CI 시간이 선형 증가하는 문제를 테스트 수를 세어 샤드 수를 자동 산출하는 방식으로 바꾸고, 빌드를 한 번만 수행해 전 샤드가 공유하게 했습니다 — CI 시간 30% 단축, 이후 테스트가 3배로 늘어난 시점에도 같은 속도 유지 (사내 기술 블로그 (https://allrafintech.co.kr/blog/137))
  • "플로우는 통과했는데 화면이 올바른가"에 답하기 위해 VRT 인프라를 구축했습니다. 환경별 렌더링 차이로 오탐이 불가피해 CI 게이트가 아닌 개발 보조 도구로 한정했고, 육안으로 놓치는 픽셀 단위 어긋남을 잡아냅니다.
  • 도메인마다 반복되는 spec·flow·목 작성을 AI Skill로 자동화하고 규칙 문서를 단일 원천으로 통합해, 새 시나리오 추가 비용과 온보딩 시간을 줄였습니다.
