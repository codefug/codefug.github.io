Next.js, TypeScript, tRPC, TanStack Query, Zustand, MSW, Playwright, Storybook

tRPC 기반 API 구조로 점진적 마이그레이션

  • Server Action 기반 기존 API 계층은 요청이 순차 처리돼 네트워크 워터폴이 불가피했고, 배포 때마다 Version Skew로 인한 요청 실패가 반복됐습니다. 서드파티 라이브러리 호환 문제도 잦았습니다.
  • 전환의 트레이드오프를 연구한 뒤 tRPC 기반 API 계층으로의 마이그레이션을 주도적으로 제안했고, 충분한 논의를 거쳐 채택됐습니다. 팀원들과 함께 도메인 단위로 점진적으로 이관해 운영 안정성을 지키면서 전환을 완료했습니다.
  • 적용 이후 요청이 병렬로 처리되며 메인 페이지 네트워크 요청 시간이 49% 감소했고, 배포 시 요청이 실패하던 현상이 사라졌습니다. 호환성 문제가 해소되면서 MSW 모킹 환경을 새로 구축하고 E2E와 스토리북의 모킹까지 통합해 개발 환경도 함께 개선했습니다.

오버레이 우선순위 조정 시스템

  • 서비스가 고도화되면서 사용자 액션 없이 조건에 따라 자동으로 뜨는 오버레이가 점점 늘어났습니다. 각 오버레이가 상태를 따로 관리하다 보니 겹쳐 뜨거나 필수 모달이 묻히는 문제가 발생했고, z-index로만 막고 있어 "누가 우선인가"가 어디에도 정의되어 있지 않아 그때마다 개별 대응이 반복됐습니다.
  • 오버레이 렌더링 로직을 중앙으로 모으고, 충돌 시 동시 노출 대신 우선순위가 가장 높은 오버레이 하나만 노출하는 OverlayCoordinator 컴포넌트를 개발해 문제를 구조적으로 해결했습니다. 오버레이가 늘어 조합이 아무리 많아져도 우선순위 선언만으로 일관되게 동작하도록 만들었습니다.

인증 상태 관리 구조 재설계

  • 기존에는 클라이언트가 자체 계산한 시각으로 세션 만료를 판단해 서버와 기준이 어긋났고, 프론트엔드 서버에서 갱신된 인증 상태를 클라이언트의 쿼리 캐시가 알 수 없는 구조적 결함도 있었습니다. 이를 일시적으로 막는 대응 코드가 점점 늘어나고 있었습니다.
  • 만료 판단 기준을 서버로 일원화하고 인증 상태 관리 구조를 재설계했습니다. ISMS 인증 요건에 맞춘 보안 정책까지 반영해 설계했고, 팀 전체가 새 구조를 이해할 수 있도록 문서화와 팀 내 공유를 진행했습니다.
  • 개선 이후 쌓여 있던 대응 코드를 모두 제거해 인증 상태를 안정적으로 관리할 수 있게 됐고, 불필요한 인증 API 호출이 사라져 성능도 함께 개선됐습니다.

E2E 확장과 CI 파이프라인 최적화

  • 테스트 수에 따라 CI 실행 시간이 선형적으로 증가하는 문제를, 리소스 낭비 없이 샤드 수를 동적으로 산출하는 파이프라인으로 해결했습니다. 테스트가 늘어나도 시간과 리소스의 트레이드오프를 조절하며 실행 시간을 관리할 수 있게 됐습니다.
  • 운영 안정성을 높이기 위해 시각적 회귀 테스트를 도입했습니다. 추후 개발 안정성을 고려해 로컬 환경에서 사용하는 도구로 설계했고, 전역적인 UI 변경 작업에서 문제를 빠르게 발견해 대응할 수 있었습니다.

문제가 재발할 수 없게 만든 구조 개선

  • 서류 첨부 플로우를 공용 상태 머신으로 통합 — useEffect에 기대어 불안정하던 흐름을 사용자 액션 기준의 상태 전이로 재설계해, 코드에 숨어 있던 레이스 컨디션과 무한 루프를 해결했습니다. 그 결과 유저당 재시도 횟수가 58% 감소했습니다.
  • 선정산 신청 로직을 Discriminated Union 기반으로 재설계 — 기존 데이터 모델은 일부 프로퍼티가 Optional로 정의돼 있어 상태별로 어떤 값이 유효한지 코드만으로 알 수 없었고, 파악하려면 백엔드 코드까지 넓게 확인해야 했습니다. 재설계 이후 잘못된 상태 조합이 타입에서 차단되어 데이터 유효성을 직관적으로 확인할 수 있게 됐습니다.
