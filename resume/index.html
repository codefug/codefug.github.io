Allra

사업자분들이 정산일 전에 매출을 미리 받을 수 있게 해주는 선정산 금융 서비스입니다. Next.js 마이그레이션이 막 끝난 시점에 합류해, 이관 과정에서 누락되거나 잘못 옮겨진 로직을 정정하고 운영 안정성을 확보했습니다.

실제 자금이 오가는 서비스인 만큼 ISMS 인증 대응이 가장 큰 과제였고, 서비스가 커지면서 배포 한 번의 복잡성과 개발 범위가 늘어 배포·테스트 환경의 중요성도 함께 커졌습니다.

Next.js, TypeScript, tRPC, Tanstack Query, Zustand, Playwright

ISMS 인증 대응 — 인증·세션 구조 재설계

  • 클라이언트가 토큰 만료 시점을 자체 계산해 선제 갱신하던 구조를, 백엔드 응답에 반응해 재발급하는 구조로 전환 — 만료 판단 기준을 서버로 일원화해 프론트·백엔드 간 불일치를 제거
  • 인증 상태 확인이 필요한 쿼리를 공용 훅으로 중앙화하여, 화면에 보이지 않는 컴포넌트가 인증 전에 요청을 보내 거절되던 불필요한 네트워크 호출을 제거
  • 에러 종류를 제대로 분류하도록 개선하고, 에러 전파를 막고 있던 로직을 제거하여 인증 게이팅을 우회하던 경로를 차단

선정산 신청 폼 상태 설계 및 반복 구현 통합

  • 쇼핑몰별 신청 상태를 6종 discriminated union으로 정의하여 화면이 표현해야 할 경우의 수를 타입으로 고정
  • 쇼핑몰별 한도·수수료·지원금을 각 자식 컴포넌트가 따로 계산하며 정책이 추가될 때마다 분기가 늘어나던 구조를, Provider가 계산을 전담하고 자식은 렌더링만 담당하도록 분리
  • 지원금이 쇼핑몰 간에 순차 소진되는 정책 때문에 한 행의 입력이 다른 행에 영향을 주는 문제를 2단계 계산 파이프라인으로 정리하고, 계산 로직을 순수 함수로 분리해 단위 테스트로 보호
  • 계약 서류 첨부가 4개 흐름에 각각 구현돼 정보확정 요청 결과가 유실되던 것을 공용 상태 머신으로 통합 — 배포 전후 실측 기준 유저당 업로드 재시도 58% 감소, 계약 체결 소요 시간 84% 단축
  • 조건에 따라 자동 노출되는 오버레이가 서로 겹쳐 뜨거나 필수 모달이 묻히던 문제를, 각 오버레이는 노출 의사만 선언하고 우선순위가 활성 1개를 결정하는 구조로 통합

테스트·배포 환경 개선

  • 복잡한 금융 플로우를 검증하기 위해 E2E 테스트를 Spec(사용자 행동)·Flow(구현)·Sequence(공통 선행 동작) 3계층으로 분리하고, API 모킹과 fixture로 엣지 케이스를 자동 재현 (사내 기술 블로그 (https://allrafintech.co.kr/blog/137))
  • 테스트 증가로 CI 시간이 선형 증가하던 문제를, 실행할 테스트 수를 세어 병렬 작업 수를 매 실행마다 산출·분배하도록 설계 — 실행 테스트가 4배로 늘어나는 동안 전체 CI 시간은 오히려 30% 감소, 테스트 1건당 CI 시간 약 80% 단축
  • 이후 병렬로 나눌수록 벽시계 시간은 줄지만 청구 시간은 늘어난다는 것을 실측으로 확인 — 중복 트리거와 실행 그룹을 정리해 머지당 청구 시간 52% 절감
  • 반복되는 테스트 코드 작성을 AI Skill로 자동화하고 관련 문서를 단일 원천으로 통합해 팀이 동일한 방식으로 사용하도록 정리
  • 디자이너·기획자가 로컬에서 직접 스토리북을 실행해야 하던 상황을, 브랜치별 프리뷰 배포를 제안·구현하여 URL만으로 UI 확인 가능하도록 개선

랜딩 페이지 성능 개선 — Lighthouse 50 → 95

  • 유입의 첫 관문인 랜딩의 병목이 LCP 18.4초였습니다. 반응형 이미지를 재설계해 브레이크포인트별 `<source>`에 독립 치수를 부여하여 뷰포트마다 레이아웃을 미리 예약하고(CLS 0.99 → 0.1), WebP 전환과 `fetchPriority` 명시로 최상단 이미지를 70KB → 30KB로 줄이면서 4배 선명하게 개선
  • 남은 TBT 600ms는 서드파티가 원인이었습니다. 관측 도구를 Datadog에서 OpenReplay로 전환하는 과정에서, 100% 샘플링으로 정적 import되어 비로그인 방문자에게도 내려가던 RUM·세션 리플레이 번들이 함께 빠졌습니다
  • 플래그로 껐다고 생각한 코드가 실제로는 번들에 남아 있었기 때문에, 제거 커밋과 그 부모를 각각 워크트리에 체크아웃해 A/B 빌드로 검증 — 랜딩 First Load JS 472KB → 413KB(−12.5%), 감소분 전부가 문제의 청크 하나였음을 확인

Next.js, TypeScript, Turborepo, Tanstack Query, Playwright

실 데이터를 건드리지 않고 검증하는 환경

  • ISMS 인증 요건에 맞춰 사용자 권한에 따른 인가 로직과 토큰 처리를 설계·구현하고, 접근 이력을 추적할 수 있는 감사 레이어를 함께 구성했습니다.
